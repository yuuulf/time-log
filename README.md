# TimeLog

作業にかかった時間を記録して、あとから振り返るための Web アプリです。

- Next.js（App Router）・React・TypeScript
- Tailwind CSS
- SQLite（better-sqlite3 + Drizzle ORM）

## 前提

- [mise](https://mise.jdx.dev/)（Node.js のバージョンを `mise.toml` で管理しています）
- GitHub CLI（`gh`。PR の作成やラベルの操作に使います）

## セットアップ

```bash
git clone https://github.com/yuuulf/time-log.git
cd time-log
mise trust      # 初回のみ。mise.toml を信頼する
mise install    # mise.toml の Node.js をインストール
npm ci          # 依存パッケージをインストール
cp .env.example .env   # 必要なら DATABASE_URL を変更
npm run dev
```

http://localhost:3000 を開くとトップページが表示されます。データベースは初めてアクセスしたときに自動で作られます。

mise が有効になっていないシェルでは、`mise exec -- npm run dev` のように `mise exec --` を付けて実行してください。

## 普段使いの起動（macOS）

開発用の `npm run dev` とは別に、自分の Mac で普段使いするための仕組みがあります。普段使い用のアプリと記録は開発用のリポジトリとは別の場所に置くので、開発の作業で普段使いの記録が変わることはありません。

### 導入

開発用のリポジトリで一度だけ実行します。

```bash
npm run local:install
```

- 普段使い用のアプリを `~/Library/Application Support/TimeLog/app` に main ブランチから用意してビルドし、ログインしたときに自動で起動するよう登録します（止まったときも起動し直します）
- 記録は `~/Library/Application Support/TimeLog/timelog.db` に置きます。初めて導入するときは、開発用の `data/timelog.db` の記録を移します（すでに普段使い用の記録があるときは上書きしません）
- 導入したら http://127.0.0.1:3100 を開きます。自分の Mac からだけ開けます
- 導入した後に開発用の `npm run dev` で記録をつけても、普段使い用の記録には入りません。普段の記録は http://127.0.0.1:3100 でつけてください

### 更新

main に変更をマージしたら、開発用のリポジトリで実行します。

```bash
npm run local:update
```

バックアップをとってから、普段使い用のアプリを main の最新にしてビルドし、起動し直します。ビルドに失敗したときは、更新前の版に戻して動かし続けます。導入と更新は `-- --branch <ブランチ名>` で main 以外のブランチも使えます。

### バックアップ

- Mac が起動しているとき、ログインしたときと毎日 12:00 に、記録のバックアップを `~/Library/Application Support/TimeLog/backups/timelog-YYYY-MM-DD.db` にとります（12:00 にスリープしていたら、起きたときにとります）
- 日付ごとに 1 つで、新しい 3 日分だけを残します。手でとるときは `npm run local:backup` を実行します
- バックアップから戻すときは、アプリを止めてから記録を置き換え、起動し直します

```bash
launchctl bootout gui/$(id -u)/local.timelog.app
cd ~/Library/Application\ Support/TimeLog
rm -f timelog.db-wal timelog.db-shm
cp backups/timelog-2026-11-20.db timelog.db   # 戻したい日付のファイル
launchctl bootstrap gui/$(id -u) ~/Library/LaunchAgents/local.timelog.app.plist
```

### ログとやめ方

- ログは `~/Library/Logs/TimeLog/`（`app.log`・`backup.log`）にあります
- mise を入れ直したときなど、アプリが起動しなくなったときは `npm run local:install` をもう一度実行します（記録はそのままです）
- 普段使いをやめるときは、launchd の登録を外して設定を消します。記録とバックアップは `~/Library/Application Support/TimeLog/` に残るので、不要なら消してください

```bash
launchctl bootout gui/$(id -u)/local.timelog.app
launchctl bootout gui/$(id -u)/local.timelog.backup
rm ~/Library/LaunchAgents/local.timelog.app.plist ~/Library/LaunchAgents/local.timelog.backup.plist
```

## 使い方

- 画面の左のサイドバーから「過去の記録」「集計」「プロジェクト」に移動できます。サイドバーには記録中のタスク（タスク名と開始時刻）も表示され、その枠を押すとトップページ（記録の開始・終了の画面）に移ります（アプリ名を押しても移ります）。記録中のあいだは、ブラウザのタブのアイコン（ファビコン）がストップウォッチに停止の四角を描いた絵に変わり、ほかのタブを見ていても記録中だと分かります。幅の狭い画面では、左上のメニューボタン（≡）でサイドバーを開きます
- タスク名を入力して開始ボタン（▶）を押すと、その時刻から記録が始まります。タスク名は省略でき、最近 30 日以内に使ったタスク名が、最近使った順に最大 10 件まで入力候補に出ます。プロジェクトも色のアイコン付きのプルダウンで選べます（省略できます）
- 終了ボタン（■）を押すと、その時刻で記録が終わり、作業時間が表示されます。記録中の経過時間は表示しません
- 記録中に別のタスクを開始すると、記録中のタスクはその時刻で自動的に終了します（記録中のタスクは 1 つまで）
- 0 時（日本時間）をまたいだ記録は、終了したときや一覧で時刻を直して保存したときに、同じタスク名・プロジェクトの日ごとの記録に分けて保存されます。前の日の記録は 23:59:59 まで、次の日の記録は 0:00:00 からになります（そのため、分けた記録の時間は日の境目ごとに 1 秒短くなります）。記録中のあいだは分けません
- トップページの「今日の記録」に、今日（日本時間）に開始した記録が表示されます。一覧のタスク名・開始時刻・終了時刻はその場で直せます。開始時刻・終了時刻はふだん時分だけを表示し、押すと日付と時分秒を直せる入力欄に変わります。値を変えて入力欄からフォーカスを外すか Enter キーを押すと保存され、Escape キーで元の値に戻ります（時刻の入力欄の中では、Tab キーは日付・時・分・秒の区切りを移ります）。入力に誤りがあるときは保存されず、理由が表示されます
- 一覧のプロジェクト（色のアイコンと名前）を押すとプルダウンが開き、選ぶとその記録のプロジェクトが変わります
- 記録を消すときは、行の右端のその他の操作のボタン（縦の三点）を押し、メニューの「削除」を選びます
- 終了した記録の再開ボタン（▶）を押すと、同じタスク名・プロジェクトで新しい記録が始まります。記録中のタスクがあれば、その時刻で自動的に終了します
- 昨日以前の記録は、サイドバーの「過去の記録」から見られます。月ごとに表示し、前の月・次の月のボタン（‹ ›）で切り替えます。開始日と終了日を入力して表示ボタン（虫めがね）を押すと、その期間（1 年以内）の記録を表示します
- サイドバーの「集計」で、月ごと（または指定した期間）の合計時間・稼働日数（記録を開始した日の数）・週ごとの集計・プロジェクトごとの集計（それぞれの合計時間と稼働日数）を見られます。月・期間の切り替えは「過去の記録」と同じです。週は月曜日で区切り、月の集計では月をまたがず、期間の集計では月をまたぐ週も 1 つにまとめます。記録中の記録の時間は合計に含めません
- 集計の期間の見出しの横の PDF 出力ボタン（ファイルと下向きの矢印）を押すと、ブラウザの印刷ダイアログが開きます。送り先に「PDF に保存」を選ぶと、期間の見出しから下の集計（サイドバーや期間の切り替えは除く）を PDF にできます。ダークモードでも白い背景で出力し、保存のファイル名は「集計 2026年11月」のように期間の見出しになります。余白は上下左右 20mm で出力します。余白を広く出すには、印刷ダイアログの余白を「デフォルト」にしてください
- サイドバーの「プロジェクト」で、プロジェクトの一覧（色のアイコン・名前・クライアント名）を見られます。一覧の「＋ 新規作成」ボタンを押すと「プロジェクトの作成」画面に移り、名前・色・クライアント名・説明を入力して右下の「作成」を押すと作成されて一覧に戻ります。色は 10 色から選びます
- 一覧のプロジェクト名を押すと詳細画面に移り、全項目をその場で直せます。値を変えて入力欄からフォーカスを外すと保存され（名前・クライアント名は Enter キーでも確定）、Escape キーで元の値に戻ります。色は選ぶとすぐに保存されます
- プロジェクトを消すときは、一覧の行の右端のその他の操作のボタン（縦の三点）を押し、メニューの「削除」を選びます。記録が紐づいているプロジェクトは削除できません
- 使わなくなったプロジェクトは、同じメニューの「アーカイブ」で一覧から外せます。アーカイブしたプロジェクトは、記録の開始や記録の一覧のプロジェクトの選択肢にも出ません（すでに紐づいている記録には、今までどおりプロジェクトが表示されます）
- 一覧の「新規作成」の横のアーカイブのボタンを押すと、アーカイブ済みのプロジェクトを見られます。メニューの「アーカイブ解除」で一覧に戻せます
- プロジェクトの紐づいた記録には、プロジェクトの色のフォルダのアイコンが表示されます。記録の一覧ではタスク名の左側にアイコンとプロジェクト名を、記録中の枠ではタスク名の上の行にアイコンとプロジェクト名を、サイドバーではタスク名の左側にアイコンだけを表示します（ポインタを合わせるとプロジェクト名が表示されます）
- 日付と時刻は日本時間で表示します
- ボタンはアイコンで表示しています。ポインタを合わせると名前（「開始」「再開」など）が表示されます

## 開発コマンド

| コマンド                | 内容                                           |
| ----------------------- | ---------------------------------------------- |
| `npm run dev`           | 開発サーバーを起動する                         |
| `npm run build`         | 本番ビルドを作る                               |
| `npm test`              | 自動テスト（Vitest）を実行する                 |
| `npm run test:watch`    | 変更を監視してテストを実行する                 |
| `npm run lint`          | ESLint でチェックする                          |
| `npm run typecheck`     | TypeScript の型チェックをする                  |
| `npm run format`        | Prettier で整形する                            |
| `npm run format:check`  | 整形されていないファイルがないか確認する       |
| `npm run db:generate`   | `lib/db/schema.ts` からマイグレーションを作る  |
| `npm run db:migrate`    | マイグレーションを手動で適用する（通常は不要） |
| `npm run local:install` | 普段使いの TimeLog を導入する（macOS）         |
| `npm run local:update`  | 普段使いの TimeLog を更新する                  |
| `npm run local:backup`  | 普段使いの記録のバックアップをとる             |

PR では GitHub Actions の CI が format:check・lint・typecheck・test・build と OpenSpec の検証を実行します。

## データベース

- データベースは SQLite のファイルです。場所は `.env` の `DATABASE_URL` で決まり、省略時は `data/timelog.db` です（`data/` は Git の管理外）
- テーブル定義は `lib/db/schema.ts` に書き、`npm run db:generate` で `drizzle/` にマイグレーションを作ってコミットします
- マイグレーションは、アプリが DB に接続するとき（初めてページを開いたとき）に自動で適用されます。テストでもインメモリの DB に同じマイグレーションが適用されます
- better-sqlite3 はネイティブモジュールです。Node.js のメジャーバージョンを上げたときは `npm rebuild better-sqlite3` を実行してください
- npm はインストールスクリプトを許可したパッケージだけ実行します（`package.json` の `allowScripts`）。better-sqlite3 などを更新して警告が出たら `npm install-scripts ls` で確認し、`npm install-scripts approve <パッケージ>` で許可してください

## 開発の進め方

開発ルールの詳細は [AGENTS.md](AGENTS.md) にあります。

### 仕様と計画（OpenSpec）

仕様と計画は [OpenSpec](https://github.com/Fission-AI/OpenSpec) で管理しています（`openspec/`）。

1. change を作り、proposal・specs・design・tasks を書く（`/opsx:propose`）
2. ブランチを切り、tasks.md に沿って実装する（`/opsx:apply`）
3. PR を作り、レビューで spec と実装が合っているかを確認する
4. tasks.md がすべて完了していることを確かめ、PR に `archive` ラベルを付ける

`archive` ラベルを付けると、GitHub Actions が PR に含まれる change をアーカイブし（`openspec/specs/` に反映し、`openspec/changes/archive/` に移す）、そのコミットを PR ブランチに追加します。tasks.md に未完了のタスクが残っているとき、またはアーカイブに失敗したときはコミットせず、理由を PR にコメントします。

新しい capability の spec ができるときは、proposal の「New Capabilities」に書いた説明が、その spec の目的（Purpose）として書き込まれます。アーカイブの後は CI と同じ OpenSpec の検証を行い、説明がない、短すぎる（50 文字未満）、要件の本文が長すぎる（500 文字超）などで通らないときはコミットせず、検証の結果と、結果に合わせた直し方の案内を PR にコメントします。直したら、ラベルを外して付け直してください。

### ブランチとコミット

- main へ直接 push せず、ブランチを切って PR を作ります
- コミットメッセージは短い日本語で書き、1 コミット 1 目的にします。フォーマットだけの変更は機能変更と分けます

main ブランチは、GitHub のリポジトリ設定（Settings → Rules → Rulesets）で次のように保護することをおすすめします。

- PR を必須にする（直接 push を禁止）
- CI の `check` ジョブを必須のステータスチェックにする
