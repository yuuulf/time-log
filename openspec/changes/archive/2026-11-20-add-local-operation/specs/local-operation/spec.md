## Purpose

自分の Mac で TimeLog を普段使いするために、開発用と分けた場所でアプリを自動で起動し、1 つのコマンドで更新し、記録を毎日バックアップできるようにする。

## ADDED Requirements

### Requirement: 普段使いの導入
システムは、開発用のリポジトリで `npm run local:install` を実行したとき、普段使い用のアプリを開発用とは別の場所（`~/Library/Application Support/TimeLog/app`）に main ブランチから用意してビルドし、自動で起動するよう登録しなければならない（SHALL）。記録は `~/Library/Application Support/TimeLog/timelog.db` に置く。この記録がまだないときは、開発用の `data/timelog.db` の記録を、書き込み途中の分も含めて移す。すでにあるときは上書きしない。もう一度実行しても、記録を失わずに同じ状態になる。

#### Scenario: 初めて導入する
- **WHEN** 開発用の `data/timelog.db` に記録がある状態で、初めて `npm run local:install` を実行する
- **THEN** 普段使い用のアプリが起動し、`http://127.0.0.1:3100` を開くと開発用と同じ記録が表示される

#### Scenario: すでに導入している状態でもう一度実行する
- **WHEN** 普段使い用の記録がある状態で `npm run local:install` を実行する
- **THEN** 普段使い用の記録は上書きされず、アプリは普段使い用の記録で動き続ける

#### Scenario: 開発用の記録がない
- **WHEN** 開発用の `data/timelog.db` がない状態で初めて `npm run local:install` を実行する
- **THEN** 普段使い用のアプリは空の記録で起動する

### Requirement: 普段使いのアプリの起動
システムは、普段使い用のアプリを、自分の Mac からだけ開ける `http://127.0.0.1:3100` で動かさなければならない（SHALL）。ログインしたときに自動で起動し、アプリが止まったときは起動し直す。開発用の `npm run dev` や開発用の記録とは、ファイルを共有しない。

#### Scenario: ログインしたときに起動する
- **WHEN** 導入済みの Mac にログインする
- **THEN** 何も操作しなくても `http://127.0.0.1:3100` で TimeLog を開ける

#### Scenario: ほかの端末からは開けない
- **WHEN** 同じネットワークのほかの端末から、この Mac のアドレスの 3100 番ポートを開く
- **THEN** TimeLog は表示されない

#### Scenario: 開発と分かれている
- **WHEN** 普段使い用のアプリが動いている間に、開発用のリポジトリで `npm run dev` や `npm run build` を実行し、開発用の記録を変える
- **THEN** 普段使い用のアプリの表示と記録は変わらない

### Requirement: 普段使いのアプリの更新
システムは、開発用のリポジトリで `npm run local:update` を実行したとき、普段使い用のアプリを main ブランチの最新にし、依存のインストールとビルドをして、アプリを起動し直さなければならない（SHALL）。ビルドに失敗したときは、更新前の版に戻してビルドし直し、アプリを動かし続け、失敗したことを伝えて終了する。更新の前に記録のバックアップをとる（「記録の毎日のバックアップ」と同じもの）。記録そのものは変えない（DB の構造の変更は、アプリを起動したときに自動で当たる）。

#### Scenario: 更新する
- **WHEN** main に新しい変更がマージされた後で `npm run local:update` を実行する
- **THEN** 普段使い用のアプリが起動し直され、新しい変更が反映され、記録はそのまま残る

#### Scenario: ビルドに失敗する
- **WHEN** main の最新がビルドできない状態で `npm run local:update` を実行する
- **THEN** 失敗したことが表示され、普段使い用のアプリは更新前の版で動き続ける

### Requirement: 記録の毎日のバックアップ
システムは、Mac が起動しているとき、普段使い用の記録のバックアップを 1 日 1 回とらなければならない（SHALL）。ログインしたときと毎日決まった時刻にとり、その時刻にスリープしていたときは起きたときにとる。バックアップは `~/Library/Application Support/TimeLog/backups/` に日付（日本時間）ごとに 1 つ作り、同じ日にもう一度とったときはその日の分を新しくする。新しい 3 日分だけを残し、それより古いものは消す。アプリが動いている間でも、書き込み途中の分を含めた壊れていないバックアップをとる。`npm run local:backup` で手でもとれる。

#### Scenario: 毎日バックアップをとる
- **WHEN** 導入済みの Mac を 2026年11月20日に起動している
- **THEN** `backups/` に 2026年11月20日のバックアップができ、TimeLog で開ける正しい記録が入っている

#### Scenario: 新しい 3 日分だけを残す
- **WHEN** 11月17日・18日・19日のバックアップがある状態で、11月20日のバックアップをとる
- **THEN** `backups/` には 18日・19日・20日の 3 つだけが残る

#### Scenario: 同じ日に何度もとる
- **WHEN** 同じ日にログインしたときと決まった時刻の 2 回バックアップをとる
- **THEN** その日のバックアップは 1 つで、新しい方の内容になっている

#### Scenario: Mac を起動していない日
- **WHEN** 11月21日に Mac を起動しなかった
- **THEN** 11月21日のバックアップは作られず、残っているバックアップは消えない
