# Design

## Context

- ファビコンは `app/layout.tsx` の `metadata.icons.icon` で、`/icon-light.png`（`media` なし）と `/icon-dark.png`（`media: "(prefers-color-scheme: dark)"`）の 2 つを出している。画像は `public/` にある 512×512px の透過 PNG
- 記録中のタスクは、サイドバーの `components/layout/RunningTask.tsx`（サーバー部品、`<Suspense>` の中）が DB を読み、`RunningTaskView.tsx` に `running`（なければ `null`）を渡して表示している
- 記録の開始・終了・修正・削除のサーバーアクション（`lib/time-entries/actions.ts`）は最後に `refresh()`（`next/cache`）を呼ぶ。これでクライアントのルーターが更新され、サイドバーの `RunningTask` も描き直される。サイドバーの記録中の表示が再読み込みなしで変わるのはこの仕組みによる
- ルートレイアウトのメタデータは静的で、`refresh()` やページの移動で中身が変わることはない

## Goals / Non-Goals

**Goals:**

- サイドバーの記録中のタスクと同じデータ・同じタイミングで、ファビコンを記録中用の絵と通常のロゴで切り替える
- 記録中でないときの見え方（今のメタデータ）は変えない

**Non-Goals:**

- ほかのタブへの即時反映（定期的な問い合わせや `BroadcastChannel` などは使わない）
- メタデータを `generateMetadata` で動的にすること

## Decisions

### 画像はユーザーの画像を透過・縮小して `public/` に置く

元の画像はユーザーが用意した `~/Downloads/TimeLog/` の 4 枚で、どれも 2000×2000px・アルファなしの RGB の PNG。ライト用（`l_`）は白地に濃い灰色、ダーク用（`d_`）は濃い灰色（`#424242` 程度）の地に白で、どちらもストップウォッチのボタンと右上の弧は青緑。記録中用は中央のチェックの代わりに赤い角丸の四角がある。

前回のロゴ（`update-app-icon`）と同じ手順で処理し、次のように置く。

| 元の画像 | 置き先 |
| --- | --- |
| `l_デフォルト.png` | `public/icon-light.png`（置き換え） |
| `d_デフォルト.png` | `public/icon-dark.png`（置き換え） |
| `l_記録中.png` | `public/icon-recording-light.png`（新規） |
| `d_記録中.png` | `public/icon-recording-dark.png`（新規） |

- 四隅から背景の色（ライト用は白、ダーク用は濃い灰色）に近い色でつながっている画素だけを透明にし、境目は背景の色との近さに応じて半透明にして色から背景の色を差し引く。512×512px に縮小する
- ストップウォッチの輪には切れ目があり、輪の内側の地も外側とつながっているので、内側も透明になる（チェックや赤い四角は透明な地の上に浮かぶ）。輪の内側だけ地を残すと、タブの色によっては四角い地や丸い地が目立つため、これでよいとする
- 処理には Next.js が依存として入れている `sharp` を、その場限りの Node.js のスクリプトから使う。スクリプトはコミットせず、PNG だけをコミットする
- 通常の絵はファイル名を変えずに置き換えるので、ファビコンとサイドバー・画面上部のロゴ（`AppLogo`）の両方が新しい絵になり、コードの変更はいらない

### ファビコンの URL を 1 か所にまとめる

`components/layout/favicons.ts` に、通常用と記録中用の URL（ライト・ダーク）を定数としてまとめる。`app/layout.tsx` のメタデータと、切り替えの部品の両方がここを参照し、URL の書き間違いで通常用と記録中用の対応が崩れないようにする。

### 切り替えはクライアント部品で `<link rel="icon">` の `href` を書き換える

`components/layout/RecordingFavicon.tsx`（`"use client"`）を作り、`recording: boolean` を受け取る。何も描かず、`useEffect` で `document.head` の `link[rel="icon"]` を探し、記録中なら通常用の URL を記録中用の URL に（ライトはライト、ダークはダークに）書き換え、記録中でなくなったときやアンマウントのときは元に戻す。`RunningTaskView` の中で `<RecordingFavicon recording={running !== null} />` として置く。

- `RunningTaskView` は `refresh()` で新しい `running` を受け取るので、ファビコンもサイドバーの表示と同じタイミングで切り替わる。追加のデータ取得はいらない
- `media` の付いた `<link>` はそのまま残し、`href` だけを変えるので、ライト・ダークの出し分けもブラウザに任せられる
- ページを移動したときに Next.js が `<head>` のファビコンの要素を作り直す場合に備え、`usePathname()` を effect の依存に入れて移動のたびに書き換え直す
- 別案: React 19 の `<link rel="icon">` を部品の中に描いて `<head>` に持ち上げさせる。メタデータの `<link>` と並んだときにどちらが使われるかはブラウザ次第で、`media` 付きのものが複数あると結果が読めないため使わない
- 別案: `generateMetadata` で記録中かどうかを読んで出し分ける。ルートレイアウトのメタデータは `refresh()` で `<head>` に反映されるとは限らず、すべてのページが DB を読む動的なメタデータになるため使わない

### テスト

- `RecordingFavicon.test.tsx`: jsdom の `document.head` に通常用の `<link rel="icon">` を 2 つ（1 つは `media` 付き）置き、`recording` が `true` なら記録中用の URL に、`false` に変えると元の URL に戻ること、アンマウントで元に戻ること、`media` は変わらないことを確かめる
- `RunningTaskView.test.tsx`: 記録中なら `<head>` のファビコンが記録中用に、記録中でなければ通常用になることを確かめる
- `app/layout.test.tsx` の既存のメタデータのテストは、URL を定数から参照する形でも同じ値であることを確かめる

### 色・文言

- 画像の中の色は画像ファイルに含まれるもので、`@theme` のトークンの対象外とする
- 新しい画面の文言はない

## Risks / Trade-offs

- [ブラウザはファビコンを強くキャッシュし、`href` を変えてもすぐ切り替わらないことがある] → URL 自体を別のファイルにしているのでキャッシュの取り違えは起きにくい。ブラウザでの確認のタスクで、開始・終了の直後に切り替わることを Chrome と Safari で確かめる
- [Safari はファビコンの `media` を無視することがある] → 今と同じく、ダークモードでもライト用が出るだけで、記録中かどうかは区別できる
- [`<Suspense>` で記録中のタスクを読み終えるまでは、記録中でも通常のロゴが出る] → 読み込みは一瞬で、その後すぐ切り替わる。最初の描画から記録中用を出すには全ページのメタデータを動的にする必要があり、見合わない
- [JavaScript が動かない環境では記録中でも通常のロゴのまま] → ファビコンは補助的な表示で、記録中の状態はサイドバーで分かる
- [ダーク用の絵は白と青緑が主なので、輪の内側まで透明にすると明るい背景の上では白い部分が見えにくい] → ダーク用は `prefers-color-scheme: dark` のときだけ使い、サイドバーでも `dark:` のときだけ出すので、明るい背景の上に出ることはない。ブラウザでの確認で見え方を確かめる
- [境目に背景の色がわずかに残ることがある] → ライト・ダークの両方の背景の上で拡大して確かめ、目立つときはしきい値を調整して作り直す
