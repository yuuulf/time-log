# Tasks

## 1. 分割の計算

- [x] 1.1 `lib/time.ts` に、開始・終了時刻を日本時間の日ごとの区間に分ける関数（例: `splitByJstDay`）を追加する（design 決定 1）。`lib/time.test.ts` で、同じ日の記録は 1 区間、23:30〜翌日 0:30 は 23:30:00〜23:59:59 と 0:00:00〜0:30 の 2 区間、3 日にまたがると間の日が 0:00:00〜23:59:59 になること、終了がちょうど翌日 0:00:00 なら分けないこと、開始が 23:59:59 より後（23:59:59.500）なら前の日の区間を作らないこと、月・年の境目（10月31日→11月1日、12月31日→1月1日）でも分かれることをテストし、`npm test` が通ることを確認する（コミット: 記録を日ごとの区間に分ける関数を追加）

## 2. 終了と修正での分割

- [x] 2.1 `lib/time-entries/repository.ts` で、記録を終わらせるときに 1.1 の関数で分割し、元の行を開始日の区間に、2 日目以降を同じタスク名・同じプロジェクトの新しい行として 1 トランザクションで保存する内部関数を作り、`stopRunningEntry` と `startEntry` の自動の終了から使う（design 決定 2・3・4）。`lib/time-entries/repository.test.ts` で、日をまたいだ記録の終了で 2 件に分かれてプロジェクトとタスク名が引き継がれること、日をまたいだ記録中に別の記録を開始すると前の記録が分かれて新しい記録が記録中になること、3 日にまたがると 3 件になること、同じ日・ちょうど 0 時の終了では分かれないことをテストし、`npm test` が通ることを確認する（コミット: 日をまたいだ記録を終了時に日ごとに分ける）
- [x] 2.2 `updateEntry` で、終了済みの記録の時刻を直して日をまたぐときに同じ方法で分割する。記録中の記録は分けない（design 決定 3）。`lib/time-entries/repository.test.ts` で、終了時刻を翌日に直すと元の記録が 23:59:59 で終わり翌日の記録が増えること、開始時刻を前の日に直すと元の記録が前の日の区間になり当日に 0:00:00 からの記録が増えること、記録中の記録の開始時刻を前の日に直しても分かれないこと、日をまたがない修正では件数が変わらないことをテストし、`npm test` が通ることを確認する（コミット: 時刻の修正で日をまたぐ記録を日ごとに分ける）
- [x] 2.3 `npm run format`・`npm run lint`・`npm run typecheck`・`npm test` を実行し、すべて通ることを確認する（フォーマットで差分が出たら、機能のコミットとは別のコミットにする）
